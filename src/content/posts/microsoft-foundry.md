## この記事でわかること

- Microsoft Foundry が何をするサービスなのか
- 「リソース」と「プロジェクト」の関係
- 「AIエージェント」とは何で、Foundry ではどんな種類が作れるのか
- はじめて触る人が、最初にやってみるとよいこと

**対象読者**：ChatGPT のような対話AIを使ったことはあるけれど、Azure や Foundry ははじめて、という人。

## 結論

- Microsoft Foundry（以前の名前は Azure AI Foundry）は、AIのモデルを使ったり、AIエージェントを作ったり、その出来を確かめたりするための Azure のサービスです。
- 中の構造は、「Foundry リソース」という大きな入れ物の中に「プロジェクト」という作業部屋がある、という2段だけ覚えれば大丈夫です。
- 最初は、画面上でAIエージェントを1つ作り、話しかけて試すのが一番早いです。プログラムを書くのはその後で構いません。

## まず言葉をそろえる

- **Azure**：Microsoft のクラウドサービスです。クラウドとは、自分のパソコンではなく、インターネットの向こうにあるコンピューターを借りて使う仕組みのことです。
- **モデル（AIモデル）**：文章を読んで、続きや答えを作るAIの本体です。GPT などが有名です。
- **AIエージェント**：モデルに「役割の説明」と「使える道具」を持たせたものです。ただ答えるだけでなく、ファイルを探す、Webを検索するなど、道具を使って作業を進められます。

## Foundry の中の構造

公式ドキュメントでは、次のように整理されています。

- **Foundry リソース**：Azure 上に作る、いちばん外側の入れ物です。ネットワークの制限、セキュリティ、使うモデルの準備（デプロイ）をここで管理します。
- **プロジェクト**：リソースの中に作る作業部屋です。作ったエージェントや、アップロードしたファイル、出来を確かめた結果は、プロジェクトごとに保存されます。
- **つながっている別のサービス**：ファイル置き場（Storage）、鍵の保管庫（Key Vault）、検索サービス（Azure AI Search）などは、Foundry とは別のサービスです。権限などは、それぞれで管理します。

たとえるなら、リソースは「建物」、プロジェクトは「その中の部屋」です。建物の入り口の警備（ネットワークやセキュリティ）は建物全体で決め、部屋の中の物（エージェントやファイル）は部屋ごとに分かれています。

実際の仕組みとしても、**プロジェクト同士のデータは分けられています**。同じプロジェクトのエージェント同士は、ファイルや会話の履歴、検索用のデータを共有できます。でも、別のプロジェクトのものには触れません。用途や利用者ごとにデータを分けたいときは、プロジェクトを分けるのが基本です。

## 作れるエージェントは3種類

| 種類 | 中身 | 向いている場面 |
|---|---|---|
| プロンプトエージェント | 指示の文章、使うモデル、使う道具を画面や設定で決めるだけ。プログラムはいらない | まず試したいとき、社内向けの簡単な道具 |
| 音声のプロンプトエージェント | 上の音声版。声で会話できる | 音声で受け答えしたいとき |
| ホステッドエージェント | 自分で書いたプログラムを、Foundry 上で動かしてもらう | 処理の流れを細かく決めたいとき |

> **コラム：「プロンプト」とは**
> プロンプトは、AIに渡す指示や質問の文章のことです。「あなたは社内の問い合わせ窓口です。丁寧に答えてください」のような文章が、エージェントの指示になります。

エージェントに持たせられる道具には、Web検索、ファイル検索、プログラムを実行する道具（コードインタープリター）、外部のサービスとつなぐ仕組み（MCP サーバー）、自分で作った関数などがあります。

## 動くときの3つの部品

エージェントを動かすとき、裏では次の3つが使われています。

- **Agent（エージェント）**：モデル＋指示＋道具をまとめた設定です。名前とバージョンを付けて保存されます。
- **Conversation（会話）**：これまでのやりとりの履歴です。サーバー側に保存されるので、続きの質問にも前の話を踏まえて答えられます。
- **Response（応答）**：1回分の実行結果です。

公式ドキュメントでも、「まずは応答（Response）だけで試す。同じ設定を何度も使いたくなったらエージェントを、履歴が必要なら会話を足す」という順番が勧められています。

## 最初にやってみること

1. プロジェクトを1つ作る（作る権限がなければ、管理している人に頼む）
2. モデルを1つ使える状態にする（デプロイする）
3. 画面上でプロンプトエージェントを作り、指示の文章を書いて、試し用の画面（プレイグラウンド）で話しかける
4. ファイル検索の道具に、公開しても問題ない資料を入れる。資料に沿って答えてくれるか確かめる
5. 記録（トレース）の画面で、エージェントがどの道具をどう使ったかを見る
6. 慣れてきたら、プログラム（SDK）からエージェントを呼んでみる。エージェントの設定をコードで管理すると、ほかの人に確認してもらったり、自動でデプロイしたりできる

仕事のデータを入れる前に、どのデータを入れてよいか、ネットワークの制限がどうなっているかを、チームに確認しておきましょう。

## 気をつけること

- 名前や画面がよく変わるサービスです。古い記事に出てくる「Azure AI Studio」「Azure AI Foundry」は、今の Microsoft Foundry と画面が違うことがあります。
- 「プレビュー」と書かれた機能は、まだ試験中です。本番で使う前に、正式版になっているか確認してください。
- 料金は、使うモデルや道具によって変わります（未確認：具体的な金額はこの記事では調べていません）。

## 用語集

| 用語 | 意味 |
|---|---|
| Azure | Microsoft のクラウドサービス |
| クラウド | インターネットの向こうのコンピューターを借りて使う仕組み |
| モデル | 文章を読んで答えを作るAIの本体 |
| プロンプト | AIに渡す指示や質問の文章 |
| AIエージェント | モデルに役割と道具を持たせ、作業を進められるようにしたもの |
| Foundry リソース | Foundry のいちばん外側の入れ物。セキュリティやモデルを管理する |
| プロジェクト | リソースの中の作業部屋。エージェントやファイルを保存する |
| デプロイ（モデルの） | モデルを、呼び出せる状態に準備すること |
| プレイグラウンド | 画面上でAIを試せる場所 |
| トレース | AIが何をしたかの記録 |
| SDK | プログラムからサービスを使うための部品集 |
| MCP | AIと外部のサービスをつなぐための共通の決まりごと |
| プレビュー | 試験中の機能。正式版ではない |
