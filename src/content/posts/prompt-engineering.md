## この記事でわかること

- 「プロンプトエンジニアリング」とは何か
- AIがまちがった答えを出すのを減らす方法
- あいまいな頼み方を、伝わる頼み方に変える方法
- 次に読むとよい公式ガイド

**対象読者**：ChatGPT などの対話AIを使ったことがある人。プログラムが書けなくても読めるように書いています。

## 結論

- AIのまちがいを減らす一番の方法は、言い回しの工夫ではなく、**答えの元になる正しい資料を渡すこと**です。
- あいまいな頼みごとは、まず「何ができたら成功か」を決めてから書きます。わからないところはAIに質問させます。
- うまくいったプロンプトは保存し、変えるたびに同じ質問で試して比べます。

## プロンプトエンジニアリングとは

**プロンプト**は、AIに渡す指示や質問の文章のことです。**プロンプトエンジニアリング**は、AIが期待どおりの答えを安定して出せるように、プロンプトを工夫することです。

AIは、同じ質問をしても毎回少し違う答えを返します。だからこそ、書き方を工夫する意味があります。

## 1. まちがった答えを減らす：資料を渡す

AIは、知らないことでも、それらしい文章で答えてしまうことがあります。この「もっともらしいまちがい」を**ハルシネーション**と呼びます。

対策は3つです。

1. **資料を渡す**：答えの元になる文書をプロンプトに入れます。
2. **資料の中だけで答えさせる**：「資料に書かれていないことは『資料にありません』と答えてください」と書きます。Microsoft の公式ガイドでも、答えが見つからないときの逃げ道を用意すると、まちがった答えを減らせると説明されています。
3. **根拠を示させる**：資料のどこに書いてあったかを引用させます。自信がない部分には「要確認」と書かせます。

> **コラム：グラウンディングと RAG**
> **グラウンディング**は、AIの答えを、渡した資料などの確かな情報に結びつけることです。
> **RAG（検索拡張生成）**はその代表的な方法です。資料が多くて全部は渡せないとき、質問に関係しそうな部分を先に検索で探し、その部分だけをAIに渡して答えさせます。
> たとえるなら、試験で「持ち込み可」にして、関係するページを開いた状態で答えさせるようなものです。実際の仕組みとしては、①質問を受け取る、②資料の山から関係する文章を検索する、③見つかった文章と質問を一緒にAIへ渡す、という3段階で動きます。
> Azure では、Azure AI Search という検索サービスに文書を入れておく構成がよく使われます（未確認：構成の詳細は公式ドキュメントで要確認）。

OpenAI の実務向けガイドには、「足りないのが正しい資料なのに、プロンプトをきれいに整えても解決しない」という趣旨の注意があります。Anthropic のガイドにも、「開いていないコードについて推測で話さない」という指示の例があります。どちらも、**まず根拠を見せる**ことを勧めています。

## 2. あいまいな頼み方を直す

「いい感じにまとめて」のような頼み方は、人に頼んでもAIに頼んでもうまくいきません。次の4つを足します。

- **成功の条件を書く**：誰が読むのか、どのくらいの長さか、どんな形（箇条書き、表など）か、何を必ず入れるか。
- **例を見せる**：「こういう入力なら、こう返してほしい」という例を1〜3個付けます。例を見せるやり方を **few-shot（フューショット）** と呼びます。
- **わからなければ質問させる**：「不明な点があれば、作業を始める前に質問してください」と書いておきます。Microsoft のガイドでも、頼みごとがあいまいなときにどうするかを、最初に決めておくよう勧めています。
- **区切りをはっきりさせる**：指示、資料、例を、見出しや `<資料>…</資料>` のようなタグで分けます。OpenAI も Anthropic もこの書き方を勧めています。

### 書き方の例

あいまいな頼み方：

```
この資料をいい感じにまとめて
```

伝わる頼み方：

```
あなたは新入社員向けの資料を作る担当です。
<資料>の内容を、はじめて読む人向けに5行の箇条書きでまとめてください。
専門用語には短い説明を付けてください。
資料に書かれていないことは書かないでください。
わからない点があれば、まとめる前に質問してください。

<資料>
（ここに資料を貼る）
</資料>
```

## 3. プロンプトを「作って終わり」にしない

Anthropic のガイドでは、プロンプトを良くしようとする前に、次の3つをそろえるよう書かれています。

1. 何ができたら成功かという基準
2. それを試す方法
3. 最初のプロンプト

OpenAI も、プロンプトをプログラムと同じように保存して変更履歴を残し、変えるたびにテストすることを勧めています。

小さく始めるなら、答えがわかっている質問を5〜10個用意します。プロンプトを変えるたびに、それを全部聞いて、前の結果と比べます。

## 4. 次に読むとよい公式ガイド

1. Anthropic「Prompt engineering overview」：全体の考え方と、改善の前にそろえるもの
2. OpenAI「Prompt engineering」：指示の書き方や、区切り方
3. OpenAI Cookbook の実務向けガイド：正確さを上げる具体的な書き方
4. Microsoft Learn「Prompt engineering techniques」：Azure 上のモデルで使うときのコツ。ただし、このページの手法は、じっくり考えるタイプのモデル（推論モデル）には向かない、とページ冒頭に書かれています
5. Microsoft Learn「System message design」：AIの役割や、迷ったときのふるまいを決める指示の作り方

## 用語集

| 用語 | 意味 |
|---|---|
| プロンプト | AIに渡す指示や質問の文章 |
| プロンプトエンジニアリング | AIが期待どおりに答えるよう、プロンプトを工夫すること |
| ハルシネーション | AIがもっともらしいまちがいを答えること |
| グラウンディング | AIの答えを、確かな資料に結びつけること |
| RAG（検索拡張生成） | 関係する資料を検索してから、AIに渡して答えさせる方法 |
| few-shot | 入力と出力の例をいくつか見せて、AIに形をまねさせる方法 |
| システムメッセージ | AIの役割やルールを決める、最初に渡す指示 |
| 推論モデル | 答える前に、内部でじっくり考えるタイプのAIモデル |
